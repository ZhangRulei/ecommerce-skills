# 退款备注判定

用于抖音、快手，不套到微信商品已退款、有赞订单已退款或拼多多实收字段。

1. 保留原备注，识别退款相关片段及记录时间。可清理匹配噪声，但不能破坏算式或记录顺序。
2. 明确的退款、退差价、赔付、补偿、小额打款、已打款均计入，不限于退款成功状态。支持人民币符号、空格、小数、中文金额，如“厂家赔付八元”。
3. 同笔退款在算式、客服与系统记录中重复出现只计一次。如“已打款56.4／小额打款56.4／均价打款56.4”为56.40元，不是三倍。
4. 可使用明确算式结果，如`39.99/3*2=26.66`。优先采用已完成实际退款／打款，而非较早拟退金额；不能单凭文本第一个或最后一个数字判断时间顺序。
5. 退款成功但没有明确部分金额：抖音按订单应付金额、快手按实付款全退。
6. 非退款成功且无明确退款记录，通常填0。快手已赔付／已理赔但无金额已被用户确认按0；抖音遇到明确已赔付但无法确定金额的新情况，先列出核对，不擅自扩展快手的特殊确认。

| 例子 | 处理 |
| --- | --- |
| 退款关闭，平台已退款11元 | 计11元，不能因状态漏计 |
| 退款成功，应付458.99元，破损补偿5元 | 计5元，不默认全额 |
| 已退款111，实付148.99元 | 计111元 |
| 先写退59.32，之后明确已退款60 | 时间及记录足以确定时取60，并留下依据 |
| 备注已退款249.99，人工表249.9 | 按备注249.99，列出0.09差异 |
| 申请退款、可售后、寄回两件，但无金额 | 不从件数、单价或物流号猜退款，执行渠道状态默认规则 |
| 两笔不同打款，各有完成记录 | 判断独立追加、累计金额或修订，不能自动相加或去重 |

正则只能提取候选金额。排除日期、订单号、电话、快递号、商品编码、件数。多次退款含义不清、金额冲突、负数或超出订单金额时列出核对，不静默取第一个数字。

每笔非默认退款保留可追溯的订单号、原表行号、原始备注、金额与依据。用户只要求新增退款列时，不擅自改写原备注、把解释塞进金额列或加很多辅助字段。可以用必要的核对清单承载疑点。

重新排序或换月份后按订单号定位，不用历史行号作为固定覆盖规则。用户只批准部分修正时，仅应用获确认部分；同事表是对照证据，不自动高于用户口径。
