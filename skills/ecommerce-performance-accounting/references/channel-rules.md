# 各渠道业绩口径

用户定制口径，2026年10月22日整理；后续明确修订优先。不是通用平台或法定财务定义。

## 抖音业绩

- 以子订单明细为粒度，对账使用子订单编号；同一主订单可含多笔合法子订单，不能按主订单编号合并或去重。
- 售后状态仅保留：退款成功、售后关闭、补寄成功、换货成功、售后已拒绝、`-`。
- 再排除订单状态“已关闭”“已发货”。收入、优惠、退款在同一批保留订单内汇总，不额外加支付时间筛选。
- 售后状态后增加“实际退款金额”，读取商家备注，执行[备注规则](refund-notes.md)。退款成功无具体部分金额时，按订单应付金额全退。
- **订单金额＝订单应付金额合计＋优惠总金额合计－实际退款金额合计。** 不用商品单价，不加退款。
- 全域商品、全域直播、乘方商品各表剔除“日期＝全部”，分别汇总整体消耗后相加；缺失某类资料需注明已提供范围，不补0。
- **业绩＝订单金额－投流总消耗。** 周报另读[独立规则](douyin-weekly.md)。

## 有赞业绩

- 排除订单状态“交易关闭”“待发货”，再排除订单退款状态“退款中”。
- 实付＝保留订单的“订单实付金额”合计。退款中的实付也要排除。
- 在同一批保留订单中，仅对“退款成功（全额退款）”“退款成功（部分退款）”汇总“订单已退款金额”。不能对筛选后的实付扣全部原始订单退款。
- **业绩＝实付－已完成退款。** 不套用备注退款、商品单价或自然周规则。
- 用户未单列投流时，汇总中的销售额与结算金额都引用这项独立业绩，推广费保持空白。

## 微信小店业绩

- 订单状态只保留“已完成”。
- **订单金额＝订单实际收款金额合计－商品已退款金额合计**，用“收款”而非“订单实际支付金额”。
- **原表逐行求和，不按订单号去重。** 同一订单因商品拆行重复展示整单收款，也按每行原值计入；不得擅自恢复曾讨论的去重方案。

| 费用 | 规则 |
| --- | --- |
| 微信豆 | 剔除充值；（消费的交易金额(个)合计－退豆的交易金额(个)合计）÷10，换算成元 |
| 视频号现金 | 剔除充值；消费的交易金额(元)合计－退还的交易金额(元)合计 |
| 小店广告 | 花费求和；有分天与汇总两张表时使用分天明细，汇总仅核对，不叠加 |
| ADQ | 花费求和 |

**业绩＝订单金额－四类费用合计。** 单店只提供一张推广数据表时，汇总其对应花费并标明已提供范围，不虚构费用分类或缺失金额。

跨月退还需核对关联消费。历史9月样本中10月1日退还已确认对应9月消费，因此计入；不能据此把未来所有跨月退款无条件并入。

## 快手业绩

- 订单状态只保留“交易成功”；售后状态只保留空白、“退款关闭”“退款成功”。
- 售后状态后增加“实际退款”。读取售后备注；实际说明在“订单备注”时使用该列并说明映射。
- 执行[备注规则](refund-notes.md)。退款成功无具体金额时，按实付款全退。其他保留状态没有明确退款、赔付、打款金额，按0；只写已理赔／已赔付但无金额也按0。
- 载体为直播进入直播订单；其他所有载体（短视频、商品卡、其他等）进入**短视频订单**，用于商品业绩核算。“商品投流”另存广告费用，不能把订单表命名为“短视频推广”。
- 各组订单金额＝本组实付款合计－本组实际退款合计。
- 直播与商品投流分别累计“花费(元)／花费”。首个数据行若为整表汇总，应排除该行，按明细和计算，说明尾差。
- **直播业绩＝直播订单金额－直播投流；商品业绩＝短视频订单金额－商品投流。**
- 核对广告账户名／ID和店铺对应关系。曾发生主店误用美妆店直播文件，不能只看文件名含“直播”就使用。

## 拼多多业绩

- 订单状态只保留“已收货”，售后只保留“无售后”或“售后取消”。源表合并标记为“无售后或售后取消”时等价保留。
- **售后处理中不计入**，即使已收货也排除。
- **订单金额＝商家实收金额(元)合计**，不用用户实付，不再额外扣一次退款。
- 在用户指定推广表累计“成交花费(元)”，不重复计入总计、说明行；不替换成交易额，也不重复相加其他费用口径。
- 用户补充的整店费用放在“全店推广”列，只填一次。广告总消耗＝成交花费合计＋全店推广合计。
- **业绩＝订单金额－广告总消耗。** 历史277.05元仅为当次补充值，未来需依据当次资料或询问是否有补充费用，不能固定套用，也不未经确认补0。

## 未知与零值

明确0元、用户确认按无退款处理和费用资料缺失是不同情况。前两者可填0；未知费用或缺字段留空并注明。部分资料可算时报告范围，不将暂算结果包装成完整利润或到账金额。
