# Excel交付规范

仅在要求生成、拆表、合并、修改文件时使用；同时读取当前电子表格技能的适用工作流。这里规定业务交付，不绑定某次运行的库版本或绝对路径。

## 文件边界

- 原始文件不覆盖。正式结果放在指定月份`核算结果/`；该目录不作为新源数据再次纳入。
- 仅给结果、不合并时保持总表不动；同时要求新增退款列或拆表时可交付独立文件。
- 合并时依据上次交付与实际内容选择最新有效文件，不机械取固定名称或最近修改时间；多个版本无法确认时再问。
- “在原表补退款列且保留全部订单”与“汇总附表剔除无效订单”不同：前者保留全部原行，后者只保留参与核算的行。不要混淆。

## 横向汇总

采用用户已确认的黄色表头横向形式：每列为平台／店铺或快手的直播、商品分组；行包含平台、店铺名称、销售额、推广费、ROI、结算金额。新增店铺顺延，不覆盖原店铺。合计及特殊占位沿用当前模板，不把历史月份占位强行复制到新模板。

- 销售额为该渠道已确认订单净额，有赞为独立业绩。
- 推广费为该店已提供净消耗，资料缺失留空并注明。
- ROI＝销售额÷推广费，费用缺失或为0时留空，不能显示除零错误。
- 结算＝销售额－推广费；有赞未单列投流时直接引用独立业绩。
- “合计（除有赞小程序外）”不含有赞；“总合计”含有赞。比率按合计分子／分母，不平均各店ROI。缺少可比口径时总ROI留空或按模板显示短横线。
- 合计仅代表已提供范围，资料缺口需简要说明，不能宣称全部成本已齐。
- 截图是布局参考，数字以本次核验结果为准。

## 完整字段明细

- 每张明细保留全部原字段及顺序，不能只选几个字段。只补必要列，如退款列、拼多多全店推广列。
- 不加标题区、配色、表格样式或统一大行高。必要的金额数值转换、日期格式与可读列宽可做；不删字段减小文件。
- 表名采用`平台_店铺名称_数据类型`，唯一且不超过31字符。必要时取仍能辨别店铺的简称。快手用“短视频订单”与“商品投流”区分，跨店费用表叫“各店铺_推广费明细”。
- 明细剔除不参与核算的订单，广告剔除已确认的重复汇总、充值行。微信订单不能因订单号相同删除。
- 末行用SUM、SUMIFS或简单差额公式显示合计，点击可看公式；合计行不能再次进入数据求和。
- 长编号保留文本精度，原备注不改写；不额外把无关收件人信息带进聊天或核对说明。

## 数字跳转

汇总数字保持数值型公式结果，同时添加Excel内部超链接，不为跳转把金额转成预格式化文本。

- 单一来源直接跳到对应明细合计。
- 跨多张投流表的推广费先跳到各店铺推广费明细的小计，各分项再跳原表合计。
- ROI、跨表结算跳到实际计算单元格；合计跳到计算依据。
- 表名、行列、合计位置变化时同步更新全部公式、内部链接和提示。
- 缺数据不创建虚假数值链接。可用蓝色数字提示可跳转；使用工作簿内目标，不是外部网页URL。

## 核验及保存

1. 独立核对记录数、收入、退款、费用、净额和源控制总计，解释尾差。
2. 检查保存后的原字段、长编号、日期、数值类型、公式与缓存结果。
3. 验证每个链接目标及公式引用存在，用可恢复的代表性金额变化检查依赖更新。
4. 检查新增或改变的视图，未改动明细复用既有核验，不重复渲染全部大表。
5. 文件占用时另存清楚命名的新版，不关闭用户程序，不声称已覆盖旧文件。

仅改名、格式或链接时不重新判定业务规则。取消压缩等可选处理就停止，不用未验证中间件替代正式结果。
