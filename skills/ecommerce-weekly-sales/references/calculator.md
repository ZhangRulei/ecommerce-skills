# 计算器使用与验收

`scripts/calculate_weekly.py`是标准库Python口径计算器，一次处理一个平台的一家店铺，输入CSV或原表头JSON记录。Excel需先用可用只读工具提取记录；不在这里解密、生成Excel或处理投放。

```text
python scripts/calculate_weekly.py --platform douyin --month 2026-10 --cutoff 2026-10-18 --coverage-start 2026-09-28 --coverage-end 2026-10-18 --shop 示例店铺 --input orders.csv --output weekly.json
```

平台参数：`douyin`、`kuaishou`、`wechat`、`pinduoduo`、`youzan`。

- 输入JSON必须为`[{"订单号":"…","订单状态":"…",...}]`数组，沿用原表头。每个文件只属于一家店铺；多店文件须按真实店铺字段先拆分，不能猜测归属。
- 规范金额、ID和日期时保留来源行号，可增加`原表行号`。Excel日期先转换成业务当地时间字符串。标识符保留字符串。
- `--month`必填，用于选择与该月相交的自然周；默认向前延至周一、向后延至周日。例如2026-10对应9月28日—11月1日，不截断跨月周。
- `--cutoff`可指定月内实际统计截止日，归属日期在该日之后的记录不进入本次金额；最后一周标签仍到周日，标注`incomplete_cutoff`。拼多多仍按订单批次归属日期处理，不用实际成交日截断。
- `--coverage-start`与`--coverage-end`必须成对提供，表示经核实的来源完整覆盖范围（含零订单日）；不能只看最早／最晚一笔订单就断言完整。未提供时周结果标为`source_coverage_unconfirmed`；周边日期未获完整覆盖时标为`incomplete_source`。
- `weeks`始终给完整周一—周日标签；不完整时金额只是已提供记录合计。`missing_source_dates`表示完整性未经覆盖范围保证的日期，不能把其金额当成已确认0。
- `total`保留为**月内累计**，按当月1日至月底／月内截止日；`full_week_range_total`为所选完整周范围的已提供记录合计。跨月时二者可以不同，不能拿周之和冒充月累计。
- CSV默认UTF-8 BOM兼容；其他编码使用`--encoding gb18030`等明确参数。
- 金额使用Decimal累计，JSON以字符串保持精度；Excel交付时金额转数值并保留公式，订单编号仍为文本。
- 输出含日汇总、自然周、累计、重复ID行数（只报告不删除）、日期异常。缺日期无法归属的记录不会伪造日期或分摊；交付时必须说明受影响的指标和金额。
- 拼多多格式明确为`YYMMDD-…`后才可调用默认批次方法；其他日期口径由执行者先确认、适配，不直接改金额以匹配旧截图。
- 退款处理忽略部分退款金额和备注，执行SKILL.md的同字段规则。所有费用、ROI、费比输出为`null`，不得转换成0。
- 缺关键字段、非空无效日期、空金额、非法金额会报错。先核实源数据，不用零值掩盖异常。

## 合成边界验证

运行：`python scripts/test_calculate_weekly.py`。

覆盖完整跨月周和独立月累计、缺少相邻月份资料、周中截止、跨年、闰年、未支付关闭订单排除退款、抖音不乘数量、跨月支付、微信同号多行保留、拼多多18日批次19日成交、有赞部分退款同字段与退款中不退、零支付比率留空及无投放值。

结构校验和脚本测试不等于以后每份新文件都正确；仍须核对真实字段、日期范围和保存后的工作簿公式。
