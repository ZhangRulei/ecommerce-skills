# 多平台总表的取数细则

以技能首页的金额表为准。下表补充各类导出的来源、时间和识别方法。

| 来源 | 识别与时间 | 容易算错的地方 |
|---|---|---|
| 抖音素材分析 | “素材名称”“素材ID”“素材来源”“素材创建时间”。按店铺分别核算。 | 标题写“主页”不改变来源分类。业绩、创建业绩、有效判定均使用“整体成交金额”。 |
| 微信小店投流 | “素材名称”“视频信息”“上传时间”。同店用视频信息中的稳定标识查重。 | 取“成交订单金额(元)”，不要误用旁边的“净成交订单金额(元)”。 |
| 视频号主页 | 按已确认的视频号名称映射归属整账号。同一视频号的不同名称应先用已确认的别名归一。 | 按账号保留主表 D 的手填值。原表短视频“成交金额”按报表期间汇总，只用作 E。D 缺失不从 E 补数。 |
| 快手个人主页／磁力金牛 | 使用“视频名称”“视频ID”“视频来源”“创建时间”。按广告账户区分。已核对的美妆账号中，“快创/高光片段”计入金牛创建清单。 | “当日总成交订单金额”的报告范围以导出设置或既有确认为准，不把下载日期当成业绩统计日。其他新来源需先核实。 |
| 腾讯 ADQ | “名称”“视频ID”“所属账户”“创建时间”“净成交订单金额”。 | 空额也可能是当月创建的资产。不能仅从非零业绩明细数创建数。 |

### 快手主页标题补充归属

仅对仍未归属的快手主页，查抖音、微信已明确归属的作品。统一全半角，去“主页-”前缀、话题和标点，按**完整标题正文**查找。所有证据唯一指向同一人才能带入；仅差句末语气词“了”的已采用例外需单独注明。记录快手 ID、对照标题、来源表和行号。共享店铺、纯数字视频名和模糊相似均不足以确定人员。已有人工确认优先；多人冲突继续待确认。

### 原表检查

统计区间用开始日（含）到末日次日（不含）。创建时间缺失要标明，不能从标题补日期。店铺导出统计期看导出条件或已确认范围；不同期间不要拼成整月。记录店铺、账户、原始文件和金额字段名。

ID 保留为文本。单店内重复键先查是否重复导出、数据粒度不同或误含合计行，跨店相同 ID 各算各店。CSV 可能是重复 BOM 或 GB18030；个别 XLSX 需重置声明过小的使用范围。金额解析千位分隔符，区分空白与零。

### 人工确认如何复用

单源助手输出 `人工确认.状态`、`条数`、`清单`。助手在终端列出清单；执行核算的 AI 负责按技能第二步真正向用户提问。快手仅因共享店铺标签出现多个候选时，应先完成上面的标题补证，再问仍有歧义的作品。

用户答复“归某人”后，把名字写入该素材的“人工确认人员”列。若维护本地映射，也可把同一条答复记入 `confirmed_materials`；该字段兼容一个确认组或多个组的数组，每组分别限定平台、店铺（含已核实别名）和年月。`records` 的 ID 用完整文本，标题按该条原值保存，`owner` 为用户确认的姓名。只有用户明确要求暂缓时才可写 `owner: "暂缓"`；此时业绩继续待确认，不重复询问。若后来确认或改判，替换该条旧记录。缺少完整 ID 时在本次工作簿按唯一证据复核，不跨期或跨店复用。真实答复保存在本地，不提交到公开仓库。

### 单源助手

在技能目录下使用 Python 3，读取 XLSX 需要 openpyxl。下面命令核对进入多平台总表的来源数据。用实际文件路径和店名替换示例：

```bash
python scripts/check_source.py "抖音导出.xlsx" --platform douyin --shop "示例店" --mapping "/path/to/private/attribution.json" --start 2026-10-01 --end 2026-10-31
python scripts/check_source.py "微信投流素材分析.xlsx" --platform wechat-ads --shop "示例店" --mapping "/path/to/private/attribution.json" --start 2026-10-01 --end 2026-10-31 --verified-period
```

映射文件由本地维护：`people` 是人员及平台账号名单，`wechat_home_aliases` 是视频号别名关系，`unconfirmed` 是尚不能确定归属的称呼；`confirmed_materials` 可省略，已有逐条确认时保留店铺、期间、文本 ID、标题和人员。格式见[合成示例](attribution.example.json)。

平台参数为 `douyin`、`wechat-ads`、`wechat-home`、`kuaishou`、`adq`。助手按平台固定取数。文件名不能证明报告期间时，须从导出面板或用户已确认的范围核实后，才用 `--verified-period`。

输出按“渠道 → 初核人员”列出金额和数量。加 `--detail-csv "新底稿.csv"` 可保存行级底稿。微信主页的 `--shop` 是视频号账号，只给 E 的原表参考金额。合并总表前，还应读入现有工作簿手填值、人工确认，按规则补充快手主页证据；不要直接把助手初核人员当作最终归属。

总表完成并重算保存后运行 `python scripts/check_report.py "多平台剪辑业绩汇总.xlsx"`。它按表头核对人员总计、各人员合计（含待确认）、渠道明细和渠道合计。当前模板的人员 D/E/F/G/H 分别对应渠道 D/E/G/H/I；渠道 F 是“有成交素材数”，不能拿它核对“当月创建素材数”。这个检查验证汇总一致性，原始金额和人员归属仍要回查来源。
